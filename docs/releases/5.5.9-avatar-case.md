# Salita Quest 5.5.9 — Avatar Case

## Purpose

The Avatar Case gives learners a small, special showcase for favourite avatars inside the existing Avatar Collection. It is deliberately separate from the equipped profile avatar.

## Four-slot collection

The case contains exactly four visible slots.

- Only avatars already owned by the active learner profile can be selected.
- Duplicate avatars are rejected.
- Empty slots remain visible.
- Avatars can be moved left or right with explicit buttons that work with mouse, keyboard and touch.
- Removing an avatar from the case does not remove ownership.
- Editing the case does not equip or unequip any avatar.

The selected IDs are stored on the account-wide learner profile as:

```text
avatarCaseIds
```

Because Tagalog and Bisaya use the same learner profile and avatar ownership, the same Avatar Case appears in both courses.

A legacy `avatarCollection.caseAvatarIds` value is accepted during startup and migrated to the top-level profile field. This prevents the normal avatar-collection state normalizer from discarding showcase state.

## Collection placement

The Avatar Case is rendered inside the existing Avatar Collection, above the full rarity catalogue. It does not create a second collection page or a second avatar ownership model.

The case picker lists only owned avatars and shows a live `selected / 4` count. The case remains usable with partially filled slots.

## Sharing

The Avatar Case uses the unified achievement-sharing controller introduced in 5.5.8.

It produces:

- a 1080 × 1080 square four-slot card;
- a 1200 × 630 Open Graph card;
- the hosted share type `avatar_case`;
- native device sharing where supported;
- image download;
- copy-link and web-composer fallbacks.

The same hosted-service failure behavior used by badges, avatars and levels remains in force. A hosted-preview outage must not prevent card generation or download.

## Responsive behavior

- Larger screens show the four case slots in one row.
- Smaller screens use a two-column case.
- The selection picker becomes a single list on narrow mobile screens.
- Dark mode is supported.
- Reordering never relies on drag-and-drop, so it remains accessible on touch and keyboard devices.

## Offline update boundary

The PWA cache advances from:

```text
salita-quest-v5-5-8-sharing-foundation-r50
```

to:

```text
salita-quest-v5-5-9-avatar-case-r51
```

The Avatar Case JavaScript and CSS are precached. Updating the PWA does not remove learner local storage.

## Learner-state safety

The feature does not write:

- `profile.avatarId`;
- `avatarCollection.equippedAvatarId`;
- owned avatar IDs;
- avatar shards;
- pending unlocks;
- XP, levels, coins or Daily Keys;
- badges or Badge Chest state;
- mastery, due dates or course progress.

## Automated acceptance

`scripts/validate-avatar-case.mjs` executes a deterministic profile-state harness and verifies:

- owned-only selection;
- duplicate rejection;
- four-slot enforcement;
- persistence;
- reordering;
- removal;
- equipped-avatar independence;
- unified `avatar_case` sharing;
- hosted-service type support;
- responsive style markers;
- offline cache coverage.

The complete Avatar Progression workflow also runs this validator.

## Manual acceptance before calling the feature visually stable

Test in both Tagalog and Bisaya:

1. Open Avatar Collection and confirm the case appears above the catalogue.
2. Add one, two, three and four owned avatars.
3. Confirm a fifth avatar cannot be added until one is removed.
4. Confirm the same avatar cannot be added twice.
5. Reorder all four positions with left and right controls.
6. Remove an avatar and confirm ownership remains.
7. Change the equipped avatar and confirm the case does not change.
8. Change the case and confirm the equipped avatar does not change.
9. Reload and switch courses; confirm the same case remains.
10. Share a partially filled case.
11. Share a full case.
12. Download the square card and inspect all four images and names.
13. Test native sharing on a supported mobile browser.
14. Test at desktop widths of 1024, 1280 and 1366 pixels at 100% zoom.
15. Test a narrow phone viewport and dark mode.
16. Update an installed PWA and confirm learner progress and the case remain intact.

Automated validation confirms state and integration rules. It does not replace these browser and visual checks.
