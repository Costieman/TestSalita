# Salita Quest 5.5.0 — Avatar Progression release checklist

This document is the final integration and release-preparation checklist for the staged 48-avatar progression feature.

## Automated release gate

The pull request must pass `.github/workflows/validate-avatar-progression-v550.yml`.

The integrated validator runs all seven component validators and then checks:

- JavaScript syntax for the catalogue, profile, collection, weekly reward, milestone reward, unlock, sharing, migration and service-worker runtimes;
- exactly 48 stable catalogue records;
- every catalogue artwork path exists and has a valid PNG, WebP or SVG signature;
- migration loads before the collection and reward runtimes;
- weekly rewards contain no random assignment;
- Levels 10–90 award only Common or Uncommon avatars;
- Level 99 awards the Golden Salita Crest;
- pending unlocks are played once and recorded;
- sharing resolves the currently equipped catalogue avatar;
- service-worker cache `salita-quest-v5-5-avatar-progression-r43` includes every catalogue asset;
- release notes and version labels identify release 5.5.0.

Run locally with:

```bash
node scripts/validate-avatar-progression-v550.mjs
```

## Required browser smoke test before merge

Test once with a new profile and once with a copy of an existing profile.

- New profile offers only Anahaw, Waling-Waling, Jade Vine and Philippine Rafflesia.
- Existing profile keeps its learner name, PIN, equipped avatar, XP, levels, mastery, due dates, streak, coins and course histories.
- Avatar Collection displays 48 entries and correct locked, partial, owned and equipped states.
- Changing the equipped avatar updates profile, desktop emblem, mobile emblem and achievement cards.
- Completing all four Daily Quests grants one account-wide key.
- Six keys permit a learner-selected Common, Uncommon or Rare target with no random assignment.
- Common, Uncommon and Rare targets add 100, 50 and 25 shards respectively.
- Unlocking an avatar queues one reveal, flies it into the collection and does not replay after acknowledgement.
- Existing Levels 10–99 receive all eligible retroactive milestone rewards exactly once.
- Tagalog and Bisaya show the same owned avatars, shards, keys, claims and equipped avatar.
- Badge, Badge Chest and Level Up cards use the equipped avatar.
- Reload while offline after one successful online load and confirm catalogue artwork and progression screens remain available.
- Reduced-motion mode acknowledges unlocks without requiring the full flight animation.

## Migration and rollback

The migration is additive and idempotent. It does not delete the original Tagalog or Bisaya course-progress JSON. Legacy weekly keys, claims, unlocked reward variants and equipped avatars are copied into the profile-level collection model.

Before merging:

1. export a representative legacy learner backup;
2. open it on the release branch and complete the smoke test;
3. export again and compare XP, mastery, schedules, coins, streak and course histories;
4. retain the pre-release main commit as the rollback point.

If a critical regression appears after deployment, revert the release merge and bump the service-worker cache name again so installed clients do not remain pinned to the defective cache.

## Release state

The feature is release-prepared only after the automated pull-request checks pass. Merging and deployment remain explicit maintainer actions.
