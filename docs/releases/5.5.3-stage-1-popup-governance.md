# Salita Quest 5.5.3 — Stage 1 popup governance

Stage 1 replaces independent level and avatar popup timers with a single popup governor. Managed popups are deduplicated, prioritised, and displayed one at a time. Existing key, weekly-reward, sharing, and placement overlays remain recognised as blockers so managed rewards do not overlap them.

## Acknowledgement-before-render

Level-up and avatar-unlock records are now saved before their animation is inserted into the page. Closing, backgrounding, or interrupting the app therefore cannot reopen the same reward indefinitely. The level runtime stores durable `levelUpsSeen` entries and cleans impossible, duplicate, already-seen, or future pending levels during startup and resume.

## Correct milestone gating

Milestone avatar rewards always recompute the learner’s actual level from the final Level Progression runtime. Cached milestone objects are not trusted. A reward is created only when the actual level qualifies and the milestone is neither claimed nor acknowledged. Invalid future claims are removed while legitimate weekly-shard ownership, non-level unlock history, and the learner’s manually equipped avatar are preserved.

Placement activity is excluded from milestone creation. The placement flow still changes course access only; it does not award XP, create level-up events, or open milestone reward popups.

## Avatar artwork

Reward artwork resolves through `getAvatarImagePath(avatarId)`, which reads the same canonical avatar catalogue used by the collection. The popup retries one failed image load, then displays a framed avatar-name fallback rather than an empty reward card.

## Mobile and PWA refresh

The service-worker cache is advanced to `salita-quest-v5-5-3-popup-governance-r46`. Tagalog and Bisaya loaders request the 5.5.3 progression, popup-governance, profile, milestone, and avatar-unlock runtimes. `mobile-refresh.html` clears stale app caches and service-worker registrations without clearing learner profiles or progress.
